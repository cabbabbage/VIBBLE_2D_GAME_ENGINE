Area UX Refactor — Areas as Assets and Micro-Rooms
==================================================

Overview
--------
This plan modernizes the dev-mode Area workflow so that every Area behaves like a first-class asset and a self-contained micro-room. Areas will live in room JSON alongside other assets, own their geometry and spawn groups, and participate in the spawn pipeline as both renderable entities and secondary spawn contexts. The legacy "Area Mode" will be fully retired in favor of capability-based interactions: left-click to edit shape, right-click for Asset Info, and double-click for Area Config. Autosave must persist every edit immediately to JSON.

Implementation Plan
-------------------
1. Persist Areas as room-scoped asset entries
   - Extend the room serialization/deserialization pipeline (`ENGINE/map_generation/room.*`) so Areas are stored in the same asset array as other room assets (e.g., `"kind": "area"`).
   - Update `Room::load_named_areas_from_json` and related helpers to instantiate asset-like Area wrappers that capture geometry, flags, and owned spawn groups.
   - Ensure runtime data structures expose Areas as both renderable assets and micro-room containers, and trigger autosave whenever Area JSON mutates.

2. Add Area creation entry point in Room Editor
   - Modify the Room Editor footer UI (`ENGINE/dev_mode/dev_footer_bar.*`) to include an "Add Area" button when a room is active.
   - On click, create a new room-scoped Area entry via the Room APIs, assign a unique name, persist the stub immediately, and launch the Area Tool to draw the polygon.

3. Refactor dev input handlers for Area interactions
   - Remove dependencies on the legacy Area Mode within `ENGINE/dev_mode/dev_controls.cpp` so pointer hit testing can identify Areas at all times.
   - Route left-clicks on Areas to the Area Tool for draw/reshape/move, right-clicks to the Area-scoped Asset Info UI, and double-clicks to the Area Config panel.
   - Maintain selection, hover, and pointer capture behaviors without relying on mode enums.

4. Extend Asset Info UI to support Area-scoped assets
   - Update `ENGINE/dev_mode/asset_info_ui.*` to accept Area entries and render applicable asset properties (visibility, z-index, tags, lighting).
   - Display a read-only preview of the Area geometry and provide an "Edit Shape" button that reopens the Area Tool.
   - Persist changes directly to the Area’s room JSON entry and trigger autosave.

5. Implement Area Config panel
   - Introduce a new dockable panel (e.g., `ENGINE/dev_mode/area_config/*`) modeled after Room Config but scoped to Areas.
   - Move Area name and expand-to-room controls into this panel and bind them to the Area JSON entry.
   - Integrate spawn group editing widgets so Area-owned spawn groups can be managed without leaving the panel.

6. Refactor spawn group ownership for Areas
   - Remove "link to area" dropdowns from spawn group editors (`ENGINE/dev_mode/spawn_group_config/*`), making ownership implicit.
   - Ensure the Area Tool stores child/impassable shapes directly under the owning Area’s JSON entry.
   - Update serialization so Room Editor and Asset Info derive Area-owned spawn groups from the Area entry instead of global IDs.

7. Extend spawn pipeline for Area micro-rooms
   - Modify spawn planners (`ENGINE/spawn/asset_spawner.*`) so Areas spawn alongside other assets, acquiring final transforms before secondary processing.
   - After the main room spawn pass, iterate spawned Areas, create scoped spawn contexts limited to each Area polygon, and execute their owned spawn groups.
   - Confirm z-index and visibility rules remain consistent in dev mode and runtime.

8. Revise Area rendering overlays
   - Update Area rendering in dev mode (`ENGINE/dev_mode/area_overlay_editor.cpp` and related overlays) to always draw Area outlines/fills based on asset metadata.
   - Implement hover and selection highlights that respect z-index, while restricting polygon handles to active Area Tool sessions.
   - Synchronize highlight state with Asset Info and Area Config selections.

9. Remove legacy Area Mode pathways
   - Delete `Mode::AreaMode`, its UI toggles, and any specialized panels that depended on it (`ENGINE/dev_mode/map_mode_ui.*`).
   - Migrate reusable shape-editing code into neutral modules, then remove obsolete Area Mode files.
   - Audit for references to "Area Mode" or `area_type`, refactoring them to the new asset-centric model.

10. Wire autosave hooks for Area edits
    - Extend autosave triggers in Room Editor, Asset Info UI, Area Tool, and spawn group widgets so every Area mutation calls `Room::save_assets_json()` immediately.
    - Ensure new Area creation and deletion operations also commit to JSON without requiring manual saves.
    - Provide unobtrusive feedback (logging/status) to confirm autosave success when editing Areas.
