CLINE TASK: Auto-refine user_tasks.csv into actionable AI plans

OBJECTIVE
For every row in repo-root/user_tasks.csv where:
  - completed == false
  - prompt_fixed == false
Use original_prompt (col 4) and related_files (col 3) to explore the repo and produce a clear, executable task plan. Write the finalized plan to ai_fixed_prompt (col 5) and set prompt_fixed to true. Do NOT change the completed column.

ASSUMPTIONS
• CSV header (exact): completed,prompt_fixed,related_files,original_prompt,ai_fixed_prompt
• related_files is a JSON array of repo-root-relative paths (strings).
• CSV uses standard quoting; escape internal double-quotes as "".
• Work at repo root; no network access needed.
• Keep one row per task; update in place (do not reorder).

ALGORITHM
1) Load CSV with strict parsing. Validate header is exactly as above.
2) For each row where completed=false AND prompt_fixed=false:
   a) Parse related_files (JSON array). Normalize to forward-slash paths, dedupe, and keep only files that exist.
   b) Use original_prompt as the intent signal. Read the listed files; if directories were mistakenly included, expand to likely relevant files (e.g., *.cpp, *.hpp, *.h, *.json, *.yaml, *.md) capped at 200 files total. Prefer files matching prompt keywords and recent modifications.
   c) Perform a lightweight repo scan to find additional files tied to the prompt (matching names, includes/imports, obvious callsites, build refs). Add only high-confidence matches. Keep the total related_files ≤ 40. Sort deterministically (alpha, case-insensitive).
   d) Synthesize a refined, implementable plan (see PLAN FORMAT). Ensure it is self-contained, names concrete files, and orders steps from first to last. Include tests/acceptance criteria.
   e) Update row fields:
      - prompt_fixed → true
      - related_files → JSON array of the final deduped file list (repo-root-relative)
      - ai_fixed_prompt → the final plan (escaped to be valid CSV)
3) Write the CSV back atomically:
   - Preserve header and row order.
   - Keep commas and newlines only within properly quoted fields.
   - Do not modify any rows that didn’t meet the criteria.

PLAN FORMAT (write into ai_fixed_prompt)
Use the following compact markdown template (no code fences inside the CSV field):

Title: <One-line imperative task title>

Goal
- <Brief objective in one sentence>

Context
- <1–3 bullets summarizing what’s broken/missing, drawn from original_prompt and code reading>

Scope of Work (ordered)
1) <Specific step naming target files>
2) <Specific step with function/class names if applicable>
3) <Migration/refactor steps with exact file paths>
…
N) <Cleanup / doc updates>

Files Affected
- <repo/path/file1>
- <repo/path/file2>
- …

Acceptance Criteria
- <Deterministic conditions that prove task is done; reference runtime behavior or tests>

Validation & Tests
- <Manual steps and/or unit tests; commands to run; expected output>

Risks & Notes
- <Edge cases, perf concerns, backward-compat notes>

Suggested Commit Message
- <Conventional commit-style single line>
- <Optional body lines>

CONSTRAINTS & QUALITY BAR
• Be precise about file paths and ordering of steps.
• If ambiguity remains, document it in “Risks & Notes” but still propose a best-effort plan.
• Avoid broad statements like “refactor module”; list exact files and symbols.
• Keep total plan under ~400 words per task for readability.
• Never change completed. Only set prompt_fixed to true once a plan is written.

OUTPUT
• A single updated user_tasks.csv on disk with the modified rows as above.
• No additional files created or deleted.

DONE WHEN
• All eligible rows have prompt_fixed=true and ai_fixed_prompt populated with a high-quality plan.
• related_files reflects the final, validated set of impacted files for each refined task.
